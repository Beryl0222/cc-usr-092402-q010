# 联合药研议事治理

创新药合作方在共同开发委员会中管理提案、回避、表决和僵局升级。

仓库保存两条经过脱敏的业务样例，源代码定义读取与复算这些样例所需的合同与流程：

- `fixtures/committee_motion.json`：v1 最小议案记录（既有标识与时间语义保持不变）。
- `fixtures/committee_session.json`：v2 可审计会议记录，由 `scripts/build_fixture.mjs` 生成，
  覆盖里程碑付款、试验方案变更、安全暂停同案审议，以及离线密封意见、临时回避重算、修订重签、
  安全紧急动作、条件性批准、通知失败待办等完整场景。

## 合同版本与迁移

- v1 只有 `schema_version / record_id / occurred_at / revision / source`。
- v2 在保持上述标识与时间含义的前提下新增 `meeting`、按生效时间保存的 `governance` 参数表，
  以及只增不改的议事轨迹集合（议案、选票、少数意见、计票、决定、更正、行动、条件、通知、审计）。
- `migrateV1(record)` 把 v1 记录迁移为 v2 空会议骨架，治理参数由秘书处补录后生效；
  `revision` 仍保持单调（v2 中等于审计轨迹长度 + 1）。

## 核心规则

- **生效时间解析**（`src/governance.js`）：成员资格、授权代表、议题范围、回避关系、材料版本、
  评议窗口、法定人数规则、表决门槛、职权全部是带 `effective_from` 的版本条目；
  同一实体取目标时点的最高版本，再判定是否到期/停用，历史任一时点都能复算出当时状态。
- **回避与资格**：回避可精确到章节；未宣布前回避或资格到期，重算立即缩小有效成员集合，
  相关已投票转入 `ineligible_seat` 账目；观察员在册但不计入有效成员。
- **议案修订与重签**（`src/motions.js`）：修订只增不改并记录受影响章节；
  只有自上次签署后被改动的章节需要重签；少数意见只可追加，任何修订与表决都不能覆盖。
- **密封意见**（`src/ballots.js`）：离线期间可提交带序列号的密封承诺，开票前公开视图只有回执；
  窗口关闭后开票内容必须与承诺一致；同一授权只计序列号最高的一票，同序列不同承诺整组作废，
  旧章节版本的票记为 stale，废票分类全部留痕。
- **计票与宣布**（`src/tally.js`）：计票是纯函数，比例比较用整数交叉相乘；
  `announceDecision` 把规则版本、有效成员、账目与摘要固化；未宣布可反复重算，
  宣布后的错误只能通过 `fileCorrection` 公开更正，原决定不被静默改写。
- **特别行动**（`src/actions.js`）：僵局升级、条件性批准、安全紧急动作各有独立职权与期限，
  逾期不静默失效而转入秘书处待办（`src/notices.js`）；通知投递失败不妨碍决定落账，
  重试以 `retry_of` 关联原通知，成功后移出待办。
- **纪要**（`src/minutes.js`）：附件按合作方 `visibility` 隐藏并只报告隐藏数量；
  完整列出规则版本、有效成员集合、材料摘要、条件、少数意见与计票账目；
  `verifyMinutes` 以记录当前状态在原宣布时点独立复算，任何人都得到相同结论。

## 本地检查

- `npm test`：合同、治理解析、选票、计票、行动、通知待办、纪要复算共 38 项检查。
- `npm run build`：对全部源文件做语法检查。
- `npm run build:fixture`：从场景脚本重新生成 v2 样例（输出确定性，可重复复算）。
